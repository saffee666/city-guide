# 内容管线

> TL;DR: 加内容 = 往 `site/src/content/` 丢一个 JSON（schema 校验是闸门）；加图 = 丢一张图进 `site/public/images/` 对应目录——两者都不改代码，build 后自动生效。
> 产出：新增城市页/路线页/景点页/图片位。

## 加一座城市

新建 `site/src/content/cities/<slug>.json`（slug = URL）。schema 13 模块全必填（见 [[架构]]）：name/nameEn/region/province/tagline/intro/getThere{short,more}/dontMiss×4/attractions 4-6/itinerary×3/food×5/stay×3/pitfalls×4/bestTime{lead,seasons×4}/specialties×4/exploreMore×4。
验证：`npx astro build`——schema 不过会直接报 InvalidContentEntryDataError。
配图：`public/images/cities/<slug>.jpg`（首页卡+城市页 hero 自动用）+ `spots/<slug>-<n>.jpg`（n=attractions 序号）。

## 加一条路线（或体验主题）

新建 `site/src/content/routes/<slug>.json`：kick（11 个枚举值之一，见 [[架构]]）+ title/lead + legs 5-12（title/label/text/href——**href 省略或 null = 渲染 soon 灰态**）+ notes×4 + related×4。
体验类主题（圣山/火锅等）加完会自动出现在 `/experiences` 对应分类。

## 加一个景点深度页

新建 `site/src/content/places/<slug>.json`（7 区 schema）。城市页 attractions 里同名景点自动变深链。

## 图片位总表（丢文件即生效）

| 目录 | 内容 | 消费方 |
|---|---|---|
| `hero/1-4.jpg` | 首页轮播 | index.astro |
| `cities/<slug>.jpg` | 城市卡+城市页 hero+目的地页+「接着去哪」 | 多处 |
| `spots/<slug>-<n>.jpg` | 城市景点卡（n=attractions 序号） | 城市页 |
| `food/<slug>-<n>.jpg` | 美食卡 | 城市页 |
| `spec/<slug>-<n>.jpg` | 特产卡 | 城市页 |
| `collections/<slug>-<n>.jpg` | 榜单排名卡（n=名次） | collections |
| `extra/quiz.jpg` `extra/lotus.jpg` | inspiration 双卡 | inspiration |

规则：文件存在→用图；不存在→渐变/汉字色块占位。**图不对就删掉该文件重新部署**，自动回落占位。

## 批量抓图脚本（site/tools/，幂等可重跑）

| 脚本 | 干什么 | 图源 |
|---|---|---|
| fetch_images.py | collections 排名卡 | Commons 搜索 |
| fetch_images2.py | hero/城市卡/景点卡 | Commons 搜索（带黑名单过滤） |
| fetch_images3.py | 美食/特产 | Commons（质量差，已弃用路线） |
| **fetch_images4.py** | 美食/特产（现行） | **zh.wikipedia 词条主图**（准确率高） |
| fix_images.py | 精确文件名修脸面图 | Commons 精确 title |

注意：Commons 搜索对中文食物/品牌命中率极低，美食类直接用 fetch_images4；跑脚本要后台+重定向日志（输出中文在 GBK 控制台会花）。
