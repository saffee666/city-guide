## 环境事实（易腐，90 天复核）

- nginx 站点根：`/var/www/city`（sites-available 模式）

- 证书：acme.sh dns_ali 签发，装在服务器上自动续期（credentials 在服务器 `~/.acme.sh/account.conf`）

## 发布流程（标准命令）

```bash
cd site && npx astro build
tar -C dist -cf - . | ssh -i ~/.ssh/alicloud_root root@39.106.188.238 \
  "tar -C /var/www/city -xf - && systemctl reload nginx && echo DEPLOYED"
```

一键脚本：`scripts/deploy.cmd`（build + push gh-pages + 提示手动 tar 步骤）。

验证发布：`curl -s --ssl-no-revoke -o /dev/null -w "%{http_code}" https://city.beichen.help/<新路径>/` → 200。
注意 Astro build 默认 directory 格式：无斜杠 URL 会 301 到带斜杠地址，验 200 要带尾斜杠。

## 常见故障（都遇到过，都是环境抖动不是配置错）

| 症状 | 处理 |
|---|---|
| curl 报 000 / exit 35（schannel TLS） | 加 `--ssl-no-revoke` + 重试，属瞬时抖动 |
| git push 报 `remote end hung up` | 直接重试一次即过 |
| git push 被拒（workflow scope） | 不要往仓库放 `.github/workflows/`；gh CLI 未授权 workflow scope |
| dev server 看不到新内容 | `npx astro dev` 重启（内容集合有缓存） |
| 图片链接 `//map/...` 打不开 | BASE_URL 拼接必须走 `B = BASE_URL.replace(/\/$/,'')` 前缀，见 [[架构]] |
